----------------------------------------------------------------------
GENERAL EXPERIMENT RULES
----------------------------------------------------------------------

1. HARD MAXIMUM LOCAL EPOCHS

    local_epochs <= 10

Never generate, recommend, tune, or run E > 10.

If an old paper/reference configuration uses E=20/40/etc., do not use
that automatically. The current project has a hard E=10 limit unless I
explicitly change this rule.

2. TUNING VS OFFICIAL NAMING

Use:
    debug_...

for:
    - hyperparameter tuning
    - screening
    - diagnostics
    - exploratory runs
    - architecture/schedule comparisons
    - fraction tests that are not yet official

Use:
    run_...

for:
    - frozen/official experiments
    - final seed replications
    - experiments where hyperparameters are already locked

Use:
    smoke_...

only for very short smoke tests.

3. NEVER SILENTLY RETUNE

If I say:
    "use locked settings"
    "official run"
    "same hyperparameters"
    "frozen hyperparameters"

then only modify the variables I explicitly ask to change.

Do NOT silently change:
    LR
    lambda
    batch size
    local epochs
    optimizer
    momentum
    weight decay
    participation
    architecture
    schedule
    number of clients
    FOLA mode
    partition method

unless required by my request.

4. CURRENT COMMON TRAINING PROFILE

Unless a specific experiment says otherwise:

    optimizer            = SGD
    local_epochs         = 10
    batch_size           = 32
    momentum             = 0.0
    weight_decay         = 0.0
    grad_clip_norm       = 10.0
    full participation   = True

For optional diagnostic source fields such as:

    max_local_steps_per_round

set them to None for normal/official experiments.

During tuning/official training, keep:

    output.save_full_client_posteriors = false

unless I explicitly request compression snapshot collection.

5. FOLA COMMON SETTINGS

For current paper-style FOLA experiments:

    mode                    = paper_reference
    lambda_scale_by_size    = false
    paper_mean_only_eval    = true

Use the locked lambda for the particular dataset/setting.

Do not confuse covariance with precision:
FOLA transmits/stores mean + diagonal precision (omega).

6. PAIRED COMPARISONS

FedAvg and FOLA paired runs must use:
    - same seed
    - same client partition
    - same client count
    - same participation
    - same requested local-data condition

Pre-generate the partition before launching the simulations.

7. TWO GPU EXECUTION MODEL

There are two RTX 5090 GPUs.

Do NOT start many independent Ray clusters simultaneously.

Preferred pattern:
    GPU0 queue -> jobs run serially
    GPU1 queue -> jobs run serially

Thus only approximately two simulations are active at once.

Use:
    scripts/_run_gpu_queue.sh

Queue files live under:
    scripts/queues/

8. OUTPUT / RESULT STYLE

I prefer results printed DIRECTLY in the terminal.

Do NOT use:
    tee
    output text files
    CSV summary files

for result presentation unless I explicitly request them.

Every simulation command response must include the matching
terminal-only result extraction command.

9. RESULT METRIC CONVENTIONS

For a run of R rounds:

    R50
        accuracy exactly at communication round 50

    R100
        accuracy exactly at round 100

    R150
        accuracy exactly at round 150

    last10
        mean accuracy across the final 10 communication rounds

        For R150:
            rounds 141-150

        For R50:
            rounds 41-50

    mean1-R
        average global test accuracy over every communication round
        from round 1 through R

        This is treated as a communication-efficiency /
        convergence-trajectory metric.

    best
        highest observed accuracy during the run

    bestR
        round where "best" occurred

When comparing FOLA and FedAvg always print:

    FOLA - FedAvg gap

in percentage points (pp).

10. RESULT ACCURACY COLUMN

For FedAvg prefer:
    accuracy
    global_accuracy
    test_accuracy

For FOLA prefer:
    fola_mean_accuracy
then fall back to:
    accuracy
    global_accuracy
    test_accuracy

Normalize to fractions internally if necessary and display as percent.

======================================================================
COMMUNICATION / FOLA PAYLOAD NOTE
======================================================================

Current FOLA transport payload is:

    mean / model parameters   float32
    precision omega           float32

Server aggregation may temporarily use float64 internally for numerical
stability but casts back to float32 for transport.

Therefore raw transmitted payload is approximately:

FedAvg:
    4P bytes per model direction

FOLA:
    8P bytes per model direction

where P = number of scalar model parameters.

Do not describe FOLA as transmitting covariance directly unless discussing
it conceptually. The implementation transfers diagonal precision omega.
