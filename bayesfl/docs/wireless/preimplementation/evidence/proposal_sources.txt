0030 ## Modeling decisions preserved
0031 
0032 - All participating clients train full local models.
0033 - Current-round importance is available before allocation; clients wait for the slowest local preparation.
0034 - Packet headers, control/grant time, server computation, and aggregation latency are omitted analytically; the bitmap remains.
0035 - A common prescribed round target defines a common upload interval.
0036 - Version B selects **any integer** count from 1 through d, then assigns B_k=L_k(m_k)/(U*c_k).
0037 - Orthogonal digital frequency resources are assumed, **not a particular OFDM waveform**.
0038 - The current derivations use bandwidth-independent spectral efficiencies. The explicit physical example uses **fixed power spectral density**, not fixed total transmit power.
0039 - Only Method 1 is developed. There is no MILP or other proposed solver in this draft.
0040 - The practical method returns a feasible incumbent and a dual-gap diagnostic/certificate where justified. Global optimality is not assumed.
0041 
0042 ## Scope
0043 
0044 The document gives a mathematical formulation, proposed allocation method, and implementation plan. No new wireless FedKLS training results are reported. General optimization references support standard dual/KKT concepts; the FedKLS-specific derivations are presented as the proposed specialization.

===== FedKLS_Wireless_Develop.zip :: IMPLEMENTATION.md =====
0001 # Suggested implementation direction
0002 
0003 This is an integration plan, not a replacement for the existing FedKLS learner. The mathematical equation numbers are in the compiled manuscript. Do not implement the client training procedure from scratch while evaluating a new allocator.
0004 
0005 ## 1. Configuration and units
0006 
0007 Use K clients, d model coordinates, b bits per mean/variance (e.g. 32), B uplink Hz, B_DL downlink Hz, and times in seconds. Keep the common round target, local training settings, and posterior estimator fixed for policy comparisons.
0008 
0009 Maintain separate variables for:
0010 - `round_target_s`: the fixed shared completion target;
0011 - `local_time_s[k]`: each client's full local preparation time;
0012 - `dl_time_s`: multicast duration;
0013 - `upload_window_s = round_target_s - dl_time_s - max(local_time_s)`;
0014 - `spectral_efficiency[k]`: positive, constant during the current bandwidth allocation;
0015 - `keep_count[k]`: integer in [1,d], never a percentage-menu index;
0016 - `bandwidth_hz[k]`: L(keep_count)/(upload_window_s * spectral_efficiency).
0017 
0018 Start with fixed client locations and block-Rayleigh fading. Use linear-scale path gains. Under the document's PSD convention:
0019 
0020     gain[k,t] = beta[k] * abs(h[k,t])**2
0021     snr[k,t] = psd_w_per_hz[k] * gain[k,t] / noise_w_per_hz
0022     c[k,t] = log2(1 + snr[k,t])
0023 
0024 Do not simultaneously keep total power fixed as bandwidth changes. Log the implied power `psd_w_per_hz[k] * bandwidth_hz[k]` and energy `power_w[k] * upload_window_s`. For automatic compliance with an intended total-power limit, a conservative sufficient setting is `psd_w_per_hz[k] * B <= Pmax_w[k]`.
0025 
0026 ## 2. Suggested interfaces
0027 
0028 The following signatures describe responsibilities, not installed library APIs:
0029 
0030     payload_bits(m: int, d: int, b: int) -> int
0031     prepare_scores(global_posterior, local_posterior) -> ClientScoreState
0032     local_price_response(state, price, weight, U, c, b) -> ClientResponse
0033     allocate_price(client_oracles, weights, U, c, B, settings) -> Allocation
0034     serialize_sparse_posterior(state, local_posterior, m) -> Packet
0035     reconstruct_and_aggregate(global_posterior, decoded_packets, weights)
0036 
0037 `ClientScoreState` holds sorted scores, coordinate indices, and tail sums. No full score vector needs to be exposed to the server. `ClientResponse` contains the selected integer count and its discarded-KL scalar. The server can derive payload and required bandwidth from the count.
0038 
0039 `Allocation` should expose counts, realized ratios, bandwidths, required total bandwidth, objective, lower bound, objective-gap diagnostic, query count, and termination status. Use statuses such as `all_dense`, `zero_distortion`, `gap_target`, `price_tolerance`, `iteration_limit`, or `infeasible`. A price tolerance is not an integer optimality certificate.
0040 
0041 ## 3. Local preparation
0042 
0043 Keep original full-model training and curvature estimation. Compute the Gaussian coordinate KL once; use strictly positive variances with identical damping in all baselines. Sort descending, retaining original coordinate indices for serialization. Construct tails using reverse cumulative summation:
0044 
0045     tail[m] = sum(sorted_scores[m:])  # zero-based indexing
0046     tail[d] = 0
0047 
0048 Use float64 for scores, tails, and allocator arithmetic initially, even if transmitted posterior values use float32. This reduces but does not mathematically eliminate rounding error.
0049 
0050 For a supplied price lambda, set the threshold `theta = 2*b*lambda/(pi*U*c)`. Count scores strictly exceeding theta and clip only to the sparse interval [1,d-1]. Compare this sparse candidate's *complete priced objective* with the dense candidate. Resolve exact ties by smaller required bandwidth. Do not skip the bitmap in this comparison.
0051 
0052 A binary search on sorted scores finds the threshold count in O(log d); evaluating the tail and dense cost then takes O(1). Selection does not trigger retraining.
0053 
0054 ## 4. Server price coordination
0055 
0056 1. Validate inputs and calculate the minimum-bandwidth feasible endpoint vector by comparing m=1 with m=d for each client. If even that vector exceeds B, return infeasible.
0057 2. Keep that vector as a feasible incumbent. Add the Version A vector if feasible and its frozen-round objective is lower.
0058 3. If all-dense demand fits, return it with zero reconstruction cost.
0059 4. Query lambda=0. Exact local minimizers have zero reconstruction cost; if that response fits, return it.
0060 5. Otherwise bracket the demand transition by doubling a positive high price until feasible, with a finite query limit and overflow checks. Keep recording bounds and feasible responses.
0061 6. Bisect the bracket. At each trial, request exact local count/cost responses, compute total required bandwidth, the response objective, and the Lagrangian lower bound. Move the low endpoint up for infeasible demand and move the high endpoint down for feasible demand.
0062 7. Maintain the best feasible objective across *all* queries. Stop on the objective gap, a price-width tolerance, or the iteration limit.
0063 8. Optionally perform a bounded number of feasible additions/dense switches. Do not call this optional greedy refinement globally optimal. Use actual piecewise payload differences at every switch.
0064 9. Recover bandwidth exactly from the feasible retained counts. Never return an infeasible final trial instead of the incumbent.
0065 
0066 The dual lower bound is valid only when local priced minima are evaluated exactly or their errors have certified bounds. An arbitrary tolerance that changes a local response can make the computed “lower bound” invalid. In ordinary floating-point experiments, label the gap a numerical diagnostic unless error control justifies a formal certificate.
0067 
0068 ## 5. End-to-end round order
0069 
0070     multicast global posterior
0071     -> parallel full local training and score preparation
0072     -> wait for all required current information
0073     -> price-response exchanges and allocation
0074     -> bandwidth grants
0075     -> concurrent posterior uploads
0076     -> prior-fill reconstruction and original weighted Gaussian-product aggregation
0077 
0078 The code may execute clients sequentially on one GPU, but the network model uses the maximum modeled local duration, not the sum of emulator wall-clock times. Keep these two times separate.
0079 
0080 If a report contains an integer count and one floating scalar per query, its control payload is small but not zero. Model transmission/framing and repeated-message latency separately; a Python function-call time is not a network latency measurement. Reserve a control allowance before optimization when an end-to-end hard target is required.
0081 
0082 ## 6. Unit and integration tests
0083 
0084 - Count 1 and count d; d=2 as a boundary case.
0085 - All zero scores and repeated threshold scores.
0086 - Sparse versus dense packet cost, including near-dense sparse packets larger than dense.
0087 - Dense feasible, minimum feasible, and infeasible budgets.
0088 - Compare each local price response with direct evaluation of every count on small d.
0089 - Verify nonincreasing actual bandwidth demand across increasing prices.
0090 - On tiny K,d only, enumerate all count combinations to check feasibility and objective bounds. This is a unit-test oracle, not the deployed solver.
0091 - Verify every output has integer counts in [1,d], sum(B_k)<=B, and L_k/(B_k*c_k)=U within declared numerical tolerance.
0092 - Reconstruct packets and compare Gaussian aggregation to existing FedKLS at identical masks and posteriors; full retention must reproduce the dense reference.
0093 - Do not renormalize client aggregation weights per coordinate.
0094 
0095 ## 7. Experimental progression
0096 
0097 First replay frozen local posteriors across channel states and budgets. This isolates allocator quality from divergent learning trajectories. Then run complete training with matched initialization, data partition, optimizer settings, channel draws, and prescribed round targets.
0098 
0099 Compare feasible equal-bandwidth adaptive retention, feasible uniform retention, and the joint allocator. Compare random coordinate selection at *matched allocated counts and bandwidths*. For each policy, log discarded KL, counts, bandwidth, time/energy accounting, control queries, gaps, deadline failures, accuracy, and calibration.
0100 
0101 Initializing the incumbent with a feasible Version A count vector prevents a worse frozen-round reconstruction objective. It does not guarantee higher multi-round test accuracy. Under fixed round lengths, the principal hypothesis is better learning within the same time budget, not necessarily faster individual rounds.

===== FedKLS_Wireless_Develop.zip :: wireless_model.tex =====
0001 \section{Wireless System and Synchronized Timing}
0002 \label{sec:system}
0003 We consider one server and $K$ participating clients indexed by $\mathcal K=\{1,\ldots,K\}$. The common neural network has $d\ge2$ scalar parameters. Client $k$ holds $n_k>0$ samples and has aggregation weight $\pi_k=n_k/\sum_j n_j$. As in FedKLS~\cite{fedkls}, each client trains the full local model and subsequently transmits selected posterior mean--variance pairs. Sparsity therefore changes the message, not the local training architecture. The proposed extension allocates bandwidth and retention based on current wireless conditions and posterior changes; it does not replace the underlying Bayesian learning algorithm.
0004 
0005 \subsection{Orthogonal Digital Links and Channel Model}
0006 Clients upload concurrently over nonoverlapping frequency resources. The allocated bandwidths satisfy
0007 \begin{equation}
0008  B_{k,t}>0,\qquad \sum_{k\in\mathcal K}B_{k,t}\le B,
0009  \label{eq:bandwidth-budget}
0010 \end{equation}
0011 where $B$ is the total uplink bandwidth. Orthogonality suppresses intra-cell interference in the analytical model. This frequency-allocation abstraction is compatible with, but does not require, a particular multicarrier waveform. In contrast, the source scheduling framework explicitly chooses OFDMA~\cite[Sec.~II-C]{scheduling}.
0012 
0013 A proposed block-fading model separates path gain and small-scale fading:
0014 \begin{equation}
0015  H_{k,t}=\sqrt{\beta_k}\,h_{k,t},\qquad
0016  \beta_k=\beta_0\left(\frac{\ell_k}{\ell_0}\right)^{-\alpha},
0017  \label{eq:channel}
0018 \end{equation}
0019 where $\ell_k\ge\ell_0>0$ is the client--server distance, $\beta_0$ is the gain at reference distance $\ell_0$, and $\alpha$ is the path-loss exponent. For the initial simulation, choose $h_{k,t}\sim\mathcal{CN}(0,1)$ independently between rounds and keep the gain fixed over the current allocation and upload phase. This Rayleigh assumption is a modeling choice, not implied by the rate formula. Fixed client positions isolate persistent distance effects from round-to-round fading. Perfect current channel knowledge is assumed for the initial allocator.
0020 
0021 The uplink uses the idealized rate model
0022 \begin{equation}
0023  R_{k,t}^{\UL}=B_{k,t}c_{k,t},\qquad
0024  c_{k,t}=\log_2(1+\gamma_{k,t}^{\UL})>0.
0025  \label{eq:rate}
0026 \end{equation}
0027 Here $c_{k,t}$ is spectral efficiency, held fixed during the bandwidth decision. One physically consistent convention is a fixed transmit power spectral density $p_{k,t}^{\mathrm{PSD}}$ (W/Hz):
0028 \begin{equation}
0029  \gamma_{k,t}^{\UL}
0030  =\frac{p_{k,t}^{\mathrm{PSD}}\beta_k|h_{k,t}|^2}{N_0},
0031  \qquad P_{k,t}=p_{k,t}^{\mathrm{PSD}}B_{k,t},
0032  \label{eq:snr-psd}
0033 \end{equation}
0034 where $N_0$ is noise power spectral density. The allocation problem does not optimize power. If a total-power limit $P_k^{\max}$ is to hold automatically without adding a bandwidth cap, a sufficient configuration is $p_{k,t}^{\mathrm{PSD}}B\le P_k^{\max}$. The actual power and energy must then be evaluated using the allocated $B_{k,t}$.
0035 
0036 Under a different convention with fixed total transmit power, the rate would instead be
0037 \begin{equation}
0038  R_{k,t}^{\UL}(B_{k,t})
0039  =B_{k,t}\log_2\!\left(1+
0040  \frac{P_{k,t}\beta_k|h_{k,t}|^2}{N_0B_{k,t}}\right).
0041  \label{eq:fixed-power-caution}
0042 \end{equation}
0043 Equation~\eqref{eq:fixed-power-caution} is not used in the derivations below. Holding both total power and SNR fixed while varying bandwidth would be inconsistent with this noise model.
0044 
0045 \subsection{Posterior Payload and Transmission Time}
0046 Let $b$ denote the bits used to represent one posterior mean or variance. Client $k$ transmits $m_{k,t}$ pairs, where
0047 \begin{equation}
0048  m_{k,t}\in\{1,\ldots,d\},\qquad
0049  r_{k,t}=\frac{m_{k,t}}{d}\in(0,1].
0050  \label{eq:retention}
0051 \end{equation}
0052 Thus, every integer retained count is allowed; no preset percentage menu is introduced. The percentage keep ratio is $100r_{k,t}$, with unavoidable resolution $100/d$ percentage points.
0053 
0054 With the submitted FedKLS bitmap representation~\cite[Sec.~II-B]{fedkls}, the uplink payload is
0055 \begin{equation}
0056  L_{k,t}^{\UL}(m)=
0057  \begin{cases}
0058  d+2bm,&1\le m<d,\\
0059  2bd,&m=d.
0060  \end{cases}
0061  \label{eq:uplink-payload}
0062 \end{equation}
0063 The $d$-bit bitmap identifies sparse coordinates. At full retention, coordinate order is known and the bitmap is omitted. Additional headers, byte padding, and packet fragmentation are neglected, but the bitmap is retained. Payload $L$ is measured in bits, not in time. Accordingly,
0064 \begin{equation}
0065  T_{k,t}^{\UL}(m_{k,t},B_{k,t})
0066  =\frac{L_{k,t}^{\UL}(m_{k,t})}{B_{k,t}c_{k,t}}.
0067  \label{eq:upload-time}
0068 \end{equation}
0069 
0070 The server sends the full global posterior by reliable digital multicast. Its payload is $2bd$ bits, counted once. Using a rate supported by the worst intended receiver, as in~\cite[Eqs.~(4)--(5)]{scheduling},
0071 \begin{equation}
0072  T_t^{\DL}=\frac{2bd}{B^{\DL}\log_2\!\left(
0073  1+\min_{k\in\mathcal K}\gamma_{k,t}^{\DL}\right)}.
0074  \label{eq:downlink-time}
0075 \end{equation}
0076 Reducing uplink retention does not shorten this dense downlink. Reliable decoding means that successfully delivered values equal their transmitted finite-precision representation; no additive channel noise is injected directly into those decoded values in the initial model. Additional quantization, packet loss, and retransmissions are outside the initial formulation.
0077 
0078 \subsection{Local Preparation and the Reporting Barrier}
0079 The general local preparation duration is
0080 \begin{align}
0081  T_{k,t}^{\local}
0082  &=T_{k,t}^{\train}+T_{k,t}^{\KL},\label{eq:local-time}\\
0083  T_{k,t}^{\train}
0084  &\simeq\frac{E_{k,t}n_kC_{\mathrm{FOLA}}}
0085  {f_{k,t}^{\mathrm{eff}}},\label{eq:train-time}
0086 \end{align}
0087 where $E_{k,t}$ is the number of local epochs, $C_{\mathrm{FOLA}}$ is the effective computation per processed example including the adopted posterior-curvature estimator, and $f_{k,t}^{\mathrm{eff}}$ is throughput in operations/s. Equation~\eqref{eq:train-time} adapts the operation-count latency model in~\cite[Eq.~(16)]{scheduling}; profiled durations may be substituted. The initial approximation $T_{k,t}^{\local}\simeq T_{k,t}^{\train}$ neglects KL computation and ranking time. Alternatively, computing a complete score ranking once permits its measured cost to be included without making local preparation depend on the allocated count.
0088 
0089 The protocol is multicast, parallel local preparation, collection of current importance information and channel information, allocation, concurrent posterior uploads, and aggregation. All clients wait until the current information required by the allocator exists. A client finishing early therefore has pre-upload waiting time
0090 \begin{equation}
0091  W_{k,t}^{\mathrm{pre}}
0092  =\max_iT_{i,t}^{\local}-T_{k,t}^{\local}.
0093  \label{eq:waiting}
0094 \end{equation}
0095 The per-client elapsed completion time is
0096 \begin{equation}
0097  \begin{split}
0098  T_{k,t}^{\round}(m_{k,t},B_{k,t})
0099  ={}&T_t^{\DL}+\max_iT_{i,t}^{\local}\\
0100  &+T_{k,t}^{\UL}(m_{k,t},B_{k,t}).
0101  \end{split}
0102  \label{eq:round-time}
0103 \end{equation}
0104 This preserves the staged structure of~\cite[Eq.~(18)]{scheduling}. In that source, the client index specifies the sole selected uploader; here it specifies an individual completion time in a multi-client round. It does not denote independent federated clocks.
0105 
0106 Channel-estimation, control-report, grant, packing, server-allocation, and aggregation durations are omitted initially. Their omission is a latency approximation, not permission to allocate using information before it is available. In particular, the proposed iterative price coordination occurs after the reporting barrier and before the main uploads.
0107 
0108 \subsection{Prescribed Common Completion Time}
0109 Let $T_t^{\round}$, without client index, be a prescribed common completion target. It and the current downlink and local durations are known when allocation begins. Define
0110 \begin{equation}
0111  U_t=T_t^{\round}-T_t^{\DL}-\max_iT_{i,t}^{\local}>0.
0112  \label{eq:uplink-budget}
0113 \end{equation}
0114 The equality-based allocation enforces $T_{k,t}^{\round}=T_t^{\round}$ for all clients, or equivalently
0115 \begin{equation}
0116  L_{k,t}^{\UL}(m_{k,t})=U_tB_{k,t}c_{k,t}.
0117  \label{eq:time-equality}
0118 \end{equation}
0119 Counts are chosen as integers, and bandwidth is then recovered as
0120 \begin{equation}
0121  B_{k,t}=\frac{L_{k,t}^{\UL}(m_{k,t})}{U_tc_{k,t}}.
0122  \label{eq:bandwidth-recovery}
0123 \end{equation}
0124 This yields exactly $U_t$ seconds of idealized uploading and may leave some total bandwidth unused. It is not the policy that uses all bandwidth to minimize completion time. At a fixed bandwidth, flooring $(U_tB_{k,t}c_{k,t}-d)/(2b)$ only enforces a sparse packet-fitting inequality, not an exact time equality.

===== FedKLS_Wireless_Develop.zip :: joint_problem.tex =====
0001 \section{Joint Bandwidth and Posterior-Retention Allocation}
0002 \label{sec:problem}
0003 \subsection{Exact Local Reconstruction Cost}
0004 Let $q_{t,0}$ be the broadcast diagonal Gaussian posterior and $q_{k,t}$ the full local diagonal Gaussian approximation after training. All variances are strictly positive. The original FedKLS omission score~\cite[Sec.~II-A]{fedkls} is
0005 \begin{align}
0006  s_{k,t,i}&=\Dkl{q_{t,0,i}}{q_{k,t,i}}\notag\\
0007  &=\frac{1}{2}\left[
0008  \frac{(\mu_{k,t,i}-\mu_{t,0,i})^2}{v_{k,t,i}}
0009  +\frac{v_{t,0,i}}{v_{k,t,i}}
0010  -1-\log\frac{v_{t,0,i}}{v_{k,t,i}}\right],
0011  \label{eq:score}
0012 \end{align}
0013 where $v$ denotes variance. Sort the scores so that $s_{k,t,(1)}\ge\cdots\ge s_{k,t,(d)}$. Let $\mathcal S_{k,t}(m)$ contain the indices of the largest $m$ scores, using a deterministic rule for ties. The server's reconstructed marginal is
0014 \begin{equation}
0015  \widetilde q_{k,t,i}(m)=
0016  \begin{cases}
0017  q_{k,t,i},&i\in\mathcal S_{k,t}(m),\\
0018  q_{t,0,i},&i\notin\mathcal S_{k,t}(m).
0019  \end{cases}
0020  \label{eq:prior-fill}
0021 \end{equation}
0022 
0023 Define the discarded-score function
0024 \begin{equation}
0025  D_{k,t}(m)=\sum_{j=m+1}^{d}s_{k,t,(j)},\qquad D_{k,t}(d)=0.
0026  \label{eq:discarded}
0027 \end{equation}
0028 It is nonincreasing since $D_{k,t}(m+1)=D_{k,t}(m)-s_{k,t,(m+1)}$. Factorization and~\eqref{eq:prior-fill} give
0029 \begin{align}
0030  \Dkl{\widetilde q_{k,t}(m)}{q_{k,t}}
0031  &=\sum_{i=1}^{d}\Dkl{\widetilde q_{k,t,i}(m)}{q_{k,t,i}}\notag\\
0032  &=\sum_{i\notin\mathcal S_{k,t}(m)}s_{k,t,i}
0033  =D_{k,t}(m).
0034  \label{eq:exact-kl}
0035 \end{align}
0036 Thus the objective measures exact reconstruction KL relative to the computed local Gaussian distributions, assuming exact delivery of retained values. It is not an exact KL to the true Bayesian posterior, global loss, or test-accuracy degradation. Top-score retention minimizes this local reconstruction cost for a fixed count. Equivalently, minimizing discarded scores maximizes retained scores because the total score is fixed during allocation.
0037 
0038 \subsection{Joint Problem and Exact Reduction}
0039 The proposed problem is
0040 \begin{equation}
0041  \begin{aligned}
0042  (\mathsf P_1)\quad
0043  \min_{\{m_{k,t},B_{k,t}\}}\quad&
0044  \sum_k\pi_k\Dkl{\widetilde q_{k,t}(m_{k,t})}{q_{k,t}}\\
0045  \mathrm{s.t.}\quad&
0046  L_{k,t}^{\UL}(m_{k,t})=U_tB_{k,t}c_{k,t},\quad\forall k,\\
0047  &\sum_kB_{k,t}\le B,\\
0048  &m_{k,t}\in\{1,\ldots,d\},\quad B_{k,t}>0.
0049  \end{aligned}
0050  \label{prob:joint}
0051 \end{equation}
0052 All $K$ clients participate. There is no whole-client exclusion variable and no allowed-ratio menu. Current local posteriors, aggregation weights, channel efficiencies, and preparation times are fixed inputs, not decision variables.
0053 
0054 Define the required bandwidth in Hz by
0055 \begin{equation}
0056  w_{k,t}(m)=\frac{L_{k,t}^{\UL}(m)}{U_tc_{k,t}}.
0057  \label{eq:bandwidth-cost}
0058 \end{equation}
0059 Substitution of~\eqref{eq:bandwidth-recovery} and~\eqref{eq:exact-kl} yields
0060 \begin{equation}
0061  \begin{aligned}
0062  (\mathsf P_2)\quad \min_{\mathbf m_t}\quad&
0063  F_t(\mathbf m_t)=\sum_k\pi_kD_{k,t}(m_{k,t})\\
0064  \mathrm{s.t.}\quad&\sum_kw_{k,t}(m_{k,t})\le B,\\
0065  &m_{k,t}\in\{1,\ldots,d\},\quad\forall k.
0066  \end{aligned}
0067  \label{prob:counts}
0068 \end{equation}
0069 
0070 \begin{proposition}
0071 For $U_t>0$, $B>0$, and $c_{k,t}>0$, problems $\mathsf P_1$ and $\mathsf P_2$ have identical feasible retained-count vectors and optimal reconstruction objectives. Every feasible $\widehat{\mathbf m}_t$ yields a feasible joint allocation through~\eqref{eq:bandwidth-recovery}.
0072 \end{proposition}
0073 \begin{proof}
0074 The time equalities uniquely impose $B_{k,t}=w_{k,t}(m_{k,t})$. Their sum satisfies~\eqref{eq:bandwidth-budget} exactly when the reduced resource constraint holds. Conversely, assigning these bandwidths to any feasible count vector satisfies each time equality. Equation~\eqref{eq:exact-kl} gives the same objective in both problems.
0075 \end{proof}
0076 The same count-feasibility condition also characterizes a model with $T_{k,t}^{\UL}\le U_t$: any feasible bandwidth can be reduced to its required value when no additional lower bandwidth limits are imposed. Equality is the selected recovery policy, not a reason to restrict counts to special ratios.
0077 
0078 \subsection{Feasibility and Endpoint Cases}
0079 Require $U_t>0$ and positive channel efficiencies. Define
0080 \begin{equation}
0081  W_t^{\min}=\sum_k\min\{w_{k,t}(1),w_{k,t}(d)\},\qquad
0082  W_t^{\dense}=\sum_kw_{k,t}(d).
0083  \label{eq:endpoint-costs}
0084 \end{equation}
0085 The minimum uses only these two endpoints because the sparse payload increases with $m$. If $W_t^{\min}>B$, the prescribed all-client problem is infeasible. If $W_t^{\dense}\le B$, full retention attains the global lower limit $F_t=0$. Otherwise, resource allocation is required, although zero scores may still permit a zero-distortion sparse solution.
0086 
0087 The dense exception is material: a near-dense sparse message with $d+2bm\ge2bd$ is weakly dominated by the dense message, which uses no more bandwidth and has zero reconstruction cost. Consequently, the payload is not globally increasing over $m=1,\ldots,d$. All comparisons below use the exact piecewise expression~\eqref{eq:uplink-payload}.

0001 \section{Lagrangian Decomposition and KL-Threshold Allocation}
0002 \label{sec:solution}
0003 We use only a shared-price Lagrangian method for the proposed allocator. Bandwidth elimination is exact, whereas the remaining integer allocation is approached through exact local price responses, a coordinated price search, and an explicitly feasible incumbent. General dual-decomposition and KKT concepts follow~\cite{decomposition,boyd}; the formulas below specialize them to the stated FedKLS objective.
0004 
0005 \subsection{Separable Local Price Problems}
0006 Suppress $t$ for this section. Introduce a multiplier $\lambda\ge0$ for the bandwidth constraint. The Lagrangian separates as
0007 \begin{equation}
0008  \mathcal L(\mathbf m,\lambda)
0009  =\sum_k\left[\pi_kD_k(m_k)+\lambda w_k(m_k)\right]-\lambda B.
0010  \label{eq:lagrangian}
0011 \end{equation}
0012 For a broadcast price, each client returns
0013 \begin{equation}
0014  m_k(\lambda)\in
0015  \argmin_{m\in\{1,\ldots,d\}}
0016  \underbrace{\left[\pi_kD_k(m)+\lambda w_k(m)\right]}_{F_k(m;\lambda)}.
0017  \label{eq:local-price}
0018 \end{equation}
0019 The client needs its own scores, $\pi_k$, $U$, and $c_k$, but not another client's posterior. The server coordinates the common price and checks the shared resource constraint. The price $\lambda$ is distinct from any regularization coefficient used in local Bayesian training.
0020 
0021 \subsection{Exact Sparse Threshold and Dense Comparison}
0022 For $1\le m\le d-2$, both $m$ and $m+1$ use the sparse format. The change in the local priced objective is
0023 \begin{align}
0024  F_k(m+1;\lambda)-F_k(m;\lambda)
0025  &=-\pi_ks_{k,(m+1)}+\lambda\frac{2b}{Uc_k}.
0026  \label{eq:marginal-change}
0027 \end{align}
0028 Thus the next pair is worth retaining when
0029 \begin{equation}
0030  s_{k,(m+1)}>\theta_k(\lambda),\qquad
0031  \theta_k(\lambda)=\frac{2b\lambda}{\pi_kUc_k}.
0032  \label{eq:threshold}
0033 \end{equation}
0034 Let $N_k(\lambda)=\#\{i:s_{k,i}>\theta_k(\lambda)\}$. Because scores decrease with rank, a sparse minimizer is
0035 \begin{equation}
0036  m_k^{\spc}(\lambda)
0037  =\min\{d-1,\max\{1,N_k(\lambda)\}\}.
0038  \label{eq:sparse-response}
0039 \end{equation}
0040 Strict thresholding selects the lowest-count sparse minimizer when scores equal the threshold. A deterministic coordinate-index rule resolves score ties when constructing the actual message.
0041 
0042 The full-retention option must be compared separately:
0043 \begin{align}
0044  F_k^{\spc}(\lambda)
0045  &=\pi_kD_k(m_k^{\spc})
0046  +\lambda\frac{d+2b m_k^{\spc}}{Uc_k},\label{eq:sparse-price}\\
0047  F_k^{\dense}(\lambda)&=\lambda\frac{2bd}{Uc_k}.
0048  \label{eq:dense-price}
0049 \end{align}
0050 Choose the candidate with smaller priced objective; in a tie choose the smaller required bandwidth, then the smaller discarded KL if necessary. Equations~\eqref{eq:sparse-response}--\eqref{eq:dense-price} solve~\eqref{eq:local-price} exactly in mathematical arithmetic. In particular, the bitmap is included even though its constant cost cancels in~\eqref{eq:marginal-change}.
0051 
0052 The resulting count is an integer computed from current scores, not an entry in a predefined ratio list. For fixed price, stronger channels and larger aggregation weights lower the threshold. Equivalently, the marginal benefit per additional Hz on the sparse branch is
0053 \begin{equation}
0054  \rho_{k,i}=\frac{\pi_kUc_ks_{k,i}}{2b},
0055  \label{eq:priority}
0056 \end{equation}
0057 and the threshold retains marginal entries with $\rho_{k,i}>\lambda$.
0058 
0059 \subsection{Server Price Search}
0060 Define the total required bandwidth and the response objective by
0061 \begin{equation}
0062  G(\lambda)=\sum_kw_k(m_k(\lambda)),\qquad
0063  F(\mathbf m(\lambda))=\sum_k\pi_kD_k(m_k(\lambda)).
0064  \label{eq:demand}
0065 \end{equation}
0066 For exact local minimizers, $G(\lambda)$ is nonincreasing, including dense-format switches. Indeed, let $m_1,m_2$ minimize one client's priced objective at $\lambda_1<\lambda_2$. Adding the two optimality inequalities gives
0067 \begin{equation}
0068  (\lambda_2-\lambda_1)\big[w_k(m_2)-w_k(m_1)\big]\le0.
0069  \label{eq:monotonicity}
0070 \end{equation}
0071 Summing over clients proves the claim. The dense exception prevents replacing bandwidth demand by an unqualified count-only proxy; the server evaluates the actual piecewise payload at every query.
0072 
0073 The server increases the price when $G(\lambda)>B$ and decreases it when a lower price may preserve more information while remaining feasible. It maintains a bracket with an infeasible low-price response and a feasible high-price response, and queries midpoint prices. An initial high price can be doubled until a feasible response is found, subject to a finite iteration and numerical-safety limit. At every query, the best feasible vector is retained rather than blindly accepting the last trial. A minimum-bandwidth vector from~\eqref{eq:endpoint-costs} provides a feasible fallback whenever the problem is feasible.
0074 
0075 After choosing $\widehat{\mathbf m}$, the server grants
0076 \begin{equation}
0077  \widehat B_k=\frac{L_k(\widehat m_k)}{Uc_k},\qquad
0078  \widehat r_k=\frac{\widehat m_k}{d}.
0079  \label{eq:final-allocation}
0080 \end{equation}
0081 Thus every idealized upload takes $U$ and the common completion target is met. Reallocating unused bandwidth to accelerate uploads would constitute a different completion policy, not the equality recovery in~\eqref{eq:final-allocation}.
0082 
0083 \subsection{Dual Bound, Stopping Rule, and Optimality Scope}
0084 The dual function is
0085 \begin{equation}
0086  g(\lambda)=\sum_k\min_{1\le m\le d,\,m\in\mathbb Z}
0087  \left[\pi_kD_k(m)+\lambda w_k(m)\right]-\lambda B.
0088  \label{eq:dual}
0089 \end{equation}
0090 For any feasible incumbent $\widehat{\mathbf m}$ and $\lambda\ge0$,
0091 \begin{equation}
0092  g(\lambda)\le F^\star\le F(\widehat{\mathbf m}),
0093  \label{eq:gap-bound}
0094 \end{equation}
0095 where $F^\star$ is the optimal value of~\eqref{prob:counts}. The first inequality follows because the Lagrangian is no greater than the primal objective at any feasible point, and $g$ minimizes that Lagrangian. The second follows from feasibility. No strong-duality assumption is needed.
0096 
0097 Over the queried prices, record
0098 \begin{equation}
0099  \mathrm{LB}=\max\{0,\max_jg(\lambda_j)\},\qquad
0100  \mathrm{UB}=F(\widehat{\mathbf m}).
0101  \label{eq:bounds}
0102 \end{equation}
0103 A requested reconstruction-objective accuracy is certified when
0104 \begin{equation}
0105  \mathrm{UB}-\mathrm{LB}
0106  \le\varepsilon_{\mathrm{abs}}+
0107  \varepsilon_{\mathrm{rel}}\max\{1,\mathrm{UB}\}.
0108  \label{eq:gap-stop}
0109 \end{equation}
0110 A price-interval tolerance or iteration cap may also stop the algorithm, but does not by itself certify this objective accuracy. If exact local responses are feasible and satisfy
0111 \begin{equation}
0112  \lambda\left(G(\lambda)-B\right)=0,
0113  \label{eq:complementarity}
0114 \end{equation}
0115 then $g(\lambda)=F(\mathbf m(\lambda))$, which certifies a global integer optimum for that instance.
0116 
0117 In general, integer counts cause stepwise demands and can leave a nonzero duality gap. Bisection cannot recover every feasible integer combination. For illustration, after mandatory minimum allocations, suppose one optional pair costs two bandwidth units and reduces weighted KL by three, while another costs three units and reduces KL by four. A remaining budget of three units favors the second pair alone, but a common price selects the first pair whenever it selects the second. This illustrates why exact local thresholding does not automatically yield a globally optimal integer allocation. The separate dense format adds another nonconvex feature.
0118 
0119 For a KKT interpretation, linearly interpolate $D_k$ between consecutive integer counts and restrict to the sparse branch. On $x\in[j,j+1]$,
0120 \begin{equation}
0121  \overline D_k(x)=D_k(j)-(x-j)s_{k,(j+1)}.
0122  \label{eq:interpolation}
0123 \end{equation}
0124 Its slopes are nondecreasing, hence it is convex. Interior KKT stationarity for this continuous relaxation~\cite[Sec.~5.5]{boyd} gives
0125 \begin{equation}
0126  0\in\pi_k\partial\overline D_k(x_k)+\lambda\frac{2b}{Uc_k}.
0127  \label{eq:kkt}
0128 \end{equation}
0129 At an interior integer breakpoint, this is
0130 \begin{equation}
0131  \pi_ks_{k,(m_k)}\ge\frac{2b\lambda}{Uc_k}
0132  \ge\pi_ks_{k,(m_k+1)}.
0133  \label{eq:kkt-threshold}
0134 \end{equation}
0135 These conditions explain the threshold but do not make the original discrete problem convex. Accordingly, a returned feasible solution is denoted $\widehat{\mathbf m}$, not $\mathbf m^\star$ unless certified.

0181 \subsection{Feasible Refinement and Computational Cost}
0182 Procedure~1 may be followed by a bounded refinement that adds affordable posterior pairs according to~\eqref{eq:priority}, and checks switches to the dense format using their actual bandwidth difference. Accept only feasible changes that do not increase the reconstruction objective. Such additions can improve the incumbent, but are not a global-optimality proof and do not remove a duality gap in general. Previously valid dual bounds remain lower bounds after refinement.
0183 
0184 A complete score sort and a reverse cumulative sum cost $O(d\log d)$ time and $O(d)$ storage at each client using a comparison sort. Afterwards, a binary search in sorted scores determines the threshold count in $O(\log d)$ time; tail evaluation and dense comparison are constant-time. Each price query uses $O(K)$ server arithmetic and a small response from each client, rather than uploading every coordinate score. With $J$ price queries, reporting scales as $O(KJ)$ scalar messages. This is a computational and signaling tradeoff, not a guarantee that repeated control exchanges have negligible elapsed time.

0003 \subsection{Separation of Learning and Allocation}
0004 Keep the existing local FOLA training and FedKLS reconstruction/aggregation intact. Introduce the wireless simulator and allocator as separate modules so that changing the resource policy does not silently change the local learner. A suggested interface is given in Table~\ref{tab:modules}. These are implementation contracts, not claims of completed training experiments.

0007 \caption{Suggested implementation modules.}

0011 \toprule
0012 Module & Responsibility and principal outputs\\
0013 \midrule
0014 Channel model & Distances, path gains, fading, PSD convention; current $c_{k,t}$ and multicast rate.\\
0015 Client preparation & Full local training, positive posterior variances, KL scores, sorted indices, and tail sums.\\
0016 Local price response & Given $\lambda,U_t,c_{k,t},\pi_k$, return exact priced count and $D_{k,t}(m)$.\\
0017 Server allocator & Check feasibility; coordinate prices; maintain incumbent, bounds, and termination status.\\
0018 Packet serializer & Send bitmap and top-$m$ pairs, or bitmap-free dense values; record actual byte count separately.\\

0020 \bottomrule

0023 
0024 For a simulated round, obtain the global posterior and downlink duration, execute each client's full local preparation, and compute $U_t$ using the maximum preparation duration. Refresh or generate channel conditions for the allocation/upload phase; do not assume an old channel measurement remains valid through arbitrarily long local training. The server then invokes Procedure~1. In an initial single-process simulator, client-response calls may be local function calls, but the server must not use the clients' full score vectors for decisions beyond the specified response interface. Account separately for the network exchanges those calls represent.
0025 
0026 After a grant, client $k$ selects its stored top-$\widehat m_{k,t}$ indices and serializes the corresponding pairs. It does not train again during the price search. The server fills omitted marginals with the broadcast global values and preserves the original normalized weighted product~\cite[Sec.~II-A]{fedkls}:
0027 \begin{equation}
0028  q_{t+1,0}(\boldsymbol\theta)
0029  \propto\prod_{k\in\mathcal K}
0030  \widetilde q_{k,t}(\boldsymbol\theta)^{\pi_k}.
0031  \label{eq:aggregation}
0032 \end{equation}
0033 Do not renormalize $\pi_k$ separately over only those clients that transmitted a particular coordinate; that would change the agreed prior-fill aggregation rule.
0034 
0035 \subsection{Numerical and Feasibility Safeguards}
0036 Use one source of truth for the piecewise payload in~\eqref{eq:uplink-payload}. Validate $U_t>0$, finite positive $c_{k,t}$, $1\le\widehat m_{k,t}\le d$, and
0037 \begin{equation}
0038  \sum_k\widehat B_{k,t}\le B,\qquad
0039  \frac{L_k(\widehat m_{k,t})}{\widehat B_{k,t}c_{k,t}}=U_t
0040  \label{eq:postconditions}
0041 \end{equation}
0042 up to declared numerical tolerances. Never round an infeasible count upward to one or silently exclude a client. A violated all-client requirement must return an infeasibility status for the experiment controller to handle explicitly.
0043 
0044 Compute score sums and objective comparisons in at least float64 for the initial numerical implementation. Construct tail sums by reverse accumulation rather than subtracting a nearly equal prefix from the total. Validate positive finite variances; apply the same damping/flooring convention to all compared learners. For variance ratio $v_0/v_k=1+u$, the variance contribution $u-\log(1+u)$ can be evaluated with a numerically stable logarithm near $u=0$. Reject nonfinite scores and distinguish tiny roundoff negatives from genuinely invalid inputs.
0045 
0046 Use deterministic score ties and dense/sparse cost ties. A numerically approximate local response need not achieve the exact local Lagrangian minimum; its evaluated value is then not automatically a valid dual lower bound. Mathematical certificates in~\eqref{eq:gap-bound} require exact local minimization or rigorously bounded numerical errors. Without such error control, label the reported gap as a numerical diagnostic. Price iterations should have explicit limits and return the best feasible incumbent on termination.
0047 
0048 The initial channel model fixes PSD, not total transmit power. Log $P_{k,t}=p_{k,t}^{\mathrm{PSD}}\widehat B_{k,t}$ and, under the equality timing policy, $E_{k,t}^{\UL}=P_{k,t}U_t$. If an experiment instead fixes total power, replace the rate and rederive the allocation cost; do not merely recompute SNR once and reuse the fixed-$c$ threshold.
0049 
0050 \subsection{Equal-Bandwidth Baseline and Controlled Comparisons}
0051 Use Version A as a baseline under the same reporting barrier and round target. Assign $B_{k,t}^{A}=B/K$ and define $Q_{k,t}=U_t(B/K)c_{k,t}$. Check $Q_{k,t}\ge2bd$ first, in which case $m_{k,t}^{A}=d$. Otherwise use
0052 \begin{equation}
0053  m_{k,t}^{A}
0054  =\min\left\{d-1,
0055  \left\lfloor\frac{Q_{k,t}-d}{2b}\right\rfloor\right\},
0056  \label{eq:version-a}
0057 \end{equation}
0058 only when the result is at least one. Infeasibility under equal bandwidth does not imply infeasibility under joint allocation. The baseline transmits within $U_t$ and can finish early; the equality-based policy recovers its own bandwidths using~\eqref{eq:final-allocation}.
0059 
0060 If Version A is feasible, its counts are feasible for the reduced joint problem because
0061 \begin{equation}
0062  \sum_kw_{k,t}(m_{k,t}^{A})\le\sum_k B/K=B.
0063  \label{eq:baseline-incumbent}
0064 \end{equation}
0065 Initializing the feasible incumbent with this vector guarantees that the returned frozen-round reconstruction objective is no worse than Version A's, since it is never replaced by a worse feasible candidate. This statement compares identical local posteriors in one round; it does not guarantee higher accuracy or domination along separate training trajectories.
0066 
0067 Start validation with frozen local posteriors. On small synthetic cases, compare the local threshold response against evaluation of all integer counts and compare the complete feasible solution against exhaustive enumeration of the tiny joint count space. Include zero scores, repeated scores, the dense exception, an all-dense feasible budget, an infeasible minimum budget, and heterogeneous $c_k$. Test that bandwidth demand is nonincreasing over increasing prices, that~\eqref{eq:postconditions} holds, and that valid lower and upper bounds bracket the tiny-instance optimum.
0068 
0069 Then evaluate repeated federated training using matched initial models, local data partitions, channel draws, training settings, and round targets. Compare joint KL-aware allocation with feasible equal-bandwidth adaptation and a uniform-retention baseline. A random-selection ablation should match retained counts and assigned bandwidths to isolate the coordinate selector. Record accuracy and calibration versus cumulative time, reconstruction objective, count distributions, bandwidths, power/energy, price-query counts, feasibility failures, and objective gaps.
0070 
0071 \subsection{Overhead Accounting and Scope of Claims}
0072 The analytical round target omits price messages and server computation, but code should separately record or model both. Wall-clock time for in-memory function calls is not wireless-report latency. If their contribution is material, reserve a control-time allowance before allocation or explicitly subtract it from the upload budget. A finite price-query cap makes such an allowance operationally meaningful. Keep simulated parallel client durations separate from the sequential runtime of a single-machine simulation.
0073 
0074 Under a fixed round duration, the intended benefit is better posterior preservation and potentially better learning within the same time budget, not an automatic reduction in per-round latency. The exact results are the reconstruction identity, bandwidth elimination, local priced solution, and conditional dual-bound certificate. The proposed price-based integer allocation is feasible by construction when the safeguards succeed, but is not universally globally optimal. Improved convergence, accuracy, calibration, and negligible control overhead remain hypotheses to be evaluated through the implementation.

0002 \section{Wireless-Aware Joint Bandwidth and Posterior-Retention Allocation}
0003 \label{sec:fedkls-wireless}
0004 \subsection{Wireless System and Synchronized Timing}
0005 \label{fkl:sec:system}
0006 We consider one server and $K$ participating clients indexed by $\mathcal K=\{1,\ldots,K\}$. The common neural network has $d\ge2$ scalar parameters. Client $k$ holds $n_k>0$ samples and has aggregation weight $\pi_k=n_k/\sum_j n_j$. As in FedKLS~\cite{fedkls}, each client trains the full local model and subsequently transmits selected posterior mean--variance pairs. Sparsity therefore changes the message, not the local training architecture. The proposed extension allocates bandwidth and retention based on current wireless conditions and posterior changes; it does not replace the underlying Bayesian learning algorithm.
0007 
0008 \subsubsection{Orthogonal Digital Links and Channel Model}
0009 Clients upload concurrently over nonoverlapping frequency resources. The allocated bandwidths satisfy
0010 \begin{equation}
0011  B_{k,t}>0,\qquad \sum_{k\in\mathcal K}B_{k,t}\le B,
0012  \label{fkl:eq:bandwidth-budget}
0013 \end{equation}
0014 where $B$ is the total uplink bandwidth. Orthogonality suppresses intra-cell interference in the analytical model. This frequency-allocation abstraction is compatible with, but does not require, a particular multicarrier waveform. In contrast, the source scheduling framework explicitly chooses OFDMA~\cite[Sec.~II-C]{scheduling}.
0015 
0016 A proposed block-fading model separates path gain and small-scale fading:
0017 \begin{equation}
0018  H_{k,t}=\sqrt{\beta_k}\,h_{k,t},\qquad
0019  \beta_k=\beta_0\left(\frac{\ell_k}{\ell_0}\right)^{-\alpha},
0020  \label{fkl:eq:channel}
0021 \end{equation}
0022 where $\ell_k\ge\ell_0>0$ is the client--server distance, $\beta_0$ is the gain at reference distance $\ell_0$, and $\alpha$ is the path-loss exponent. For the initial simulation, choose $h_{k,t}\sim\mathcal{CN}(0,1)$ independently between rounds and keep the gain fixed over the current allocation and upload phase. This Rayleigh assumption is a modeling choice, not implied by the rate formula. Fixed client positions isolate persistent distance effects from round-to-round fading. Perfect current channel knowledge is assumed for the initial allocator.
0023 
0024 The uplink uses the idealized rate model
0025 \begin{equation}
0026  R_{k,t}^{\UL}=B_{k,t}c_{k,t},\qquad
0027  c_{k,t}=\log_2(1+\gamma_{k,t}^{\UL})>0.
0028  \label{fkl:eq:rate}
0029 \end{equation}
0030 Here $c_{k,t}$ is spectral efficiency, held fixed during the bandwidth decision. One physically consistent convention is a fixed transmit power spectral density $p_{k,t}^{\mathrm{PSD}}$ (W/Hz):
0031 \begin{equation}
0032  \gamma_{k,t}^{\UL}
0033  =\frac{p_{k,t}^{\mathrm{PSD}}\beta_k|h_{k,t}|^2}{N_0},
0034  \qquad P_{k,t}=p_{k,t}^{\mathrm{PSD}}B_{k,t},
0035  \label{fkl:eq:snr-psd}
0036 \end{equation}
0037 where $N_0$ is noise power spectral density. The allocation problem does not optimize power. If a total-power limit $P_k^{\max}$ is to hold automatically without adding a bandwidth cap, a sufficient configuration is $p_{k,t}^{\mathrm{PSD}}B\le P_k^{\max}$. The actual power and energy must then be evaluated using the allocated $B_{k,t}$.
0038 
0039 Under a different convention with fixed total transmit power, the rate would instead be
0040 \begin{equation}
0041  R_{k,t}^{\UL}(B_{k,t})
0042  =B_{k,t}\log_2\!\left(1+
0043  \frac{P_{k,t}\beta_k|h_{k,t}|^2}{N_0B_{k,t}}\right).
0044  \label{fkl:eq:fixed-power-caution}
0045 \end{equation}
0046 Equation~\eqref{fkl:eq:fixed-power-caution} is not used in the derivations below. Holding both total power and SNR fixed while varying bandwidth would be inconsistent with this noise model.
0047 
0048 \subsubsection{Posterior Payload and Transmission Time}
0049 Let $b$ denote the bits used to represent one posterior mean or variance. Client $k$ transmits $m_{k,t}$ pairs, where
0050 \begin{equation}
0051  m_{k,t}\in\{1,\ldots,d\},\qquad
0052  r_{k,t}=\frac{m_{k,t}}{d}\in(0,1].
0053  \label{fkl:eq:retention}
0054 \end{equation}
0055 Thus, every integer retained count is allowed; no preset percentage menu is introduced. The percentage keep ratio is $100r_{k,t}$, with unavoidable resolution $100/d$ percentage points.
0056 
0057 With the submitted FedKLS bitmap representation~\cite[Sec.~II-B]{fedkls}, the uplink payload is
0058 \begin{equation}
0059  L_{k,t}^{\UL}(m)=
0060  \begin{cases}
0061  d+2bm,&1\le m<d,\\
0062  2bd,&m=d.
0063  \end{cases}
0064  \label{fkl:eq:uplink-payload}
0065 \end{equation}
0066 The $d$-bit bitmap identifies sparse coordinates. At full retention, coordinate order is known and the bitmap is omitted. Additional headers, byte padding, and packet fragmentation are neglected, but the bitmap is retained. Payload $L$ is measured in bits, not in time. Accordingly,
0067 \begin{equation}
0068  T_{k,t}^{\UL}(m_{k,t},B_{k,t})
0069  =\frac{L_{k,t}^{\UL}(m_{k,t})}{B_{k,t}c_{k,t}}.
0070  \label{fkl:eq:upload-time}
0071 \end{equation}
0072 
0073 The server sends the full global posterior by reliable digital multicast. Its payload is $2bd$ bits, counted once. Using a rate supported by the worst intended receiver, as in~\cite[Eqs.~(4)--(5)]{scheduling},
0074 \begin{equation}
0075  T_t^{\DL}=\frac{2bd}{B^{\DL}\log_2\!\left(
0076  1+\min_{k\in\mathcal K}\gamma_{k,t}^{\DL}\right)}.
0077  \label{fkl:eq:downlink-time}
0078 \end{equation}
0079 Reducing uplink retention does not shorten this dense downlink. Reliable decoding means that successfully delivered values equal their transmitted finite-precision representation; no additive channel noise is injected directly into those decoded values in the initial model. Additional quantization, packet loss, and retransmissions are outside the initial formulation.
0080 
0081 \subsubsection{Local Preparation and the Reporting Barrier}
0082 The general local preparation duration is
0083 \begin{align}
0084  T_{k,t}^{\local}
0085  &=T_{k,t}^{\train}+T_{k,t}^{\KL},\label{fkl:eq:local-time}\\
0086  T_{k,t}^{\train}
0087  &\simeq\frac{E_{k,t}n_kC_{\mathrm{FOLA}}}
0088  {f_{k,t}^{\mathrm{eff}}},\label{fkl:eq:train-time}
0089 \end{align}
0090 where $E_{k,t}$ is the number of local epochs, $C_{\mathrm{FOLA}}$ is the effective computation per processed example including the adopted posterior-curvature estimator, and $f_{k,t}^{\mathrm{eff}}$ is throughput in operations/s. Equation~\eqref{fkl:eq:train-time} adapts the operation-count latency model in~\cite[Eq.~(16)]{scheduling}; profiled durations may be substituted. The initial approximation $T_{k,t}^{\local}\simeq T_{k,t}^{\train}$ neglects KL computation and ranking time. Alternatively, computing a complete score ranking once permits its measured cost to be included without making local preparation depend on the allocated count.
0091 
0092 The protocol is multicast, parallel local preparation, collection of current importance information and channel information, allocation, concurrent posterior uploads, and aggregation. All clients wait until the current information required by the allocator exists. A client finishing early therefore has pre-upload waiting time
0093 \begin{equation}
0094  W_{k,t}^{\mathrm{pre}}
0095  =\max_iT_{i,t}^{\local}-T_{k,t}^{\local}.
0096  \label{fkl:eq:waiting}
0097 \end{equation}
0098 The per-client elapsed completion time is
0099 \begin{equation}
0100  \begin{split}
0101  T_{k,t}^{\round}(m_{k,t},B_{k,t})
0102  ={}&T_t^{\DL}+\max_iT_{i,t}^{\local}\\
0103  &+T_{k,t}^{\UL}(m_{k,t},B_{k,t}).
0104  \end{split}
0105  \label{fkl:eq:round-time}
0106 \end{equation}
0107 This preserves the staged structure of~\cite[Eq.~(18)]{scheduling}. In that source, the client index specifies the sole selected uploader; here it specifies an individual completion time in a multi-client round. It does not denote independent federated clocks.
0108 
0109 Channel-estimation, control-report, grant, packing, server-allocation, and aggregation durations are omitted initially. Their omission is a latency approximation, not permission to allocate using information before it is available. In particular, the proposed iterative price coordination occurs after the reporting barrier and before the main uploads.
0110 
0111 \subsubsection{Prescribed Common Completion Time}
0112 Let $T_t^{\round}$, without client index, be a prescribed common completion target. It and the current downlink and local durations are known when allocation begins. Define
0113 \begin{equation}
0114  U_t=T_t^{\round}-T_t^{\DL}-\max_iT_{i,t}^{\local}>0.
0115  \label{fkl:eq:uplink-budget}
0116 \end{equation}
0117 The equality-based allocation enforces $T_{k,t}^{\round}=T_t^{\round}$ for all clients, or equivalently
0118 \begin{equation}
0119  L_{k,t}^{\UL}(m_{k,t})=U_tB_{k,t}c_{k,t}.
0120  \label{fkl:eq:time-equality}
0121 \end{equation}
0122 Counts are chosen as integers, and bandwidth is then recovered as
0123 \begin{equation}
0124  B_{k,t}=\frac{L_{k,t}^{\UL}(m_{k,t})}{U_tc_{k,t}}.
0125  \label{fkl:eq:bandwidth-recovery}
0126 \end{equation}
0127 This yields exactly $U_t$ seconds of idealized uploading and may leave some total bandwidth unused. It is not the policy that uses all bandwidth to minimize completion time. At a fixed bandwidth, flooring $(U_tB_{k,t}c_{k,t}-d)/(2b)$ only enforces a sparse packet-fitting inequality, not an exact time equality.

0130 \subsection{Joint Bandwidth and Posterior-Retention Allocation}
0131 \label{fkl:sec:problem}
0132 \subsubsection{Exact Local Reconstruction Cost}
0133 Let $q_{t,0}$ be the broadcast diagonal Gaussian posterior and $q_{k,t}$ the full local diagonal Gaussian approximation after training. All variances are strictly positive. The original FedKLS omission score~\cite[Sec.~II-A]{fedkls} is
0134 \begin{align}
0135  s_{k,t,i}&=\Dkl{q_{t,0,i}}{q_{k,t,i}}\notag\\
0136  &=\frac{1}{2}\left[
0137  \frac{(\mu_{k,t,i}-\mu_{t,0,i})^2}{v_{k,t,i}}
0138  +\frac{v_{t,0,i}}{v_{k,t,i}}
0139  -1-\log\frac{v_{t,0,i}}{v_{k,t,i}}\right],
0140  \label{fkl:eq:score}
0141 \end{align}
0142 where $v$ denotes variance. Sort the scores so that $s_{k,t,(1)}\ge\cdots\ge s_{k,t,(d)}$. Let $\mathcal S_{k,t}(m)$ contain the indices of the largest $m$ scores, using a deterministic rule for ties. The server's reconstructed marginal is
0143 \begin{equation}
0144  \widetilde q_{k,t,i}(m)=
0145  \begin{cases}
0146  q_{k,t,i},&i\in\mathcal S_{k,t}(m),\\
0147  q_{t,0,i},&i\notin\mathcal S_{k,t}(m).
0148  \end{cases}
0149  \label{fkl:eq:prior-fill}
0150 \end{equation}
0151 
0152 Define the discarded-score function
0153 \begin{equation}
0154  D_{k,t}(m)=\sum_{j=m+1}^{d}s_{k,t,(j)},\qquad D_{k,t}(d)=0.
0155  \label{fkl:eq:discarded}
0156 \end{equation}
0157 It is nonincreasing since $D_{k,t}(m+1)=D_{k,t}(m)-s_{k,t,(m+1)}$. Factorization and~\eqref{fkl:eq:prior-fill} give
0158 \begin{align}
0159  \Dkl{\widetilde q_{k,t}(m)}{q_{k,t}}
0160  &=\sum_{i=1}^{d}\Dkl{\widetilde q_{k,t,i}(m)}{q_{k,t,i}}\notag\\
0161  &=\sum_{i\notin\mathcal S_{k,t}(m)}s_{k,t,i}
0162  =D_{k,t}(m).
0163  \label{fkl:eq:exact-kl}
0164 \end{align}
0165 Thus the objective measures exact reconstruction KL relative to the computed local Gaussian distributions, assuming exact delivery of retained values. It is not an exact KL to the true Bayesian posterior, global loss, or test-accuracy degradation. Top-score retention minimizes this local reconstruction cost for a fixed count. Equivalently, minimizing discarded scores maximizes retained scores because the total score is fixed during allocation.
0166 
0167 \subsubsection{Joint Problem and Exact Reduction}
0168 The proposed problem is
0169 \begin{equation}
0170  \begin{aligned}
0171  (\mathsf P_1)\quad
0172  \min_{\{m_{k,t},B_{k,t}\}}\quad&
0173  \sum_k\pi_k\Dkl{\widetilde q_{k,t}(m_{k,t})}{q_{k,t}}\\
0174  \mathrm{s.t.}\quad&
0175  L_{k,t}^{\UL}(m_{k,t})=U_tB_{k,t}c_{k,t},\quad\forall k,\\
0176  &\sum_kB_{k,t}\le B,\\
0177  &m_{k,t}\in\{1,\ldots,d\},\quad B_{k,t}>0.
0178  \end{aligned}
0179  \label{fkl:prob:joint}
0180 \end{equation}
0181 All $K$ clients participate. There is no whole-client exclusion variable and no allowed-ratio menu. Current local posteriors, aggregation weights, channel efficiencies, and preparation times are fixed inputs, not decision variables.
0182 
0183 Define the required bandwidth in Hz by
0184 \begin{equation}
0185  w_{k,t}(m)=\frac{L_{k,t}^{\UL}(m)}{U_tc_{k,t}}.
0186  \label{fkl:eq:bandwidth-cost}
0187 \end{equation}
0188 Substitution of~\eqref{fkl:eq:bandwidth-recovery} and~\eqref{fkl:eq:exact-kl} yields
0189 \begin{equation}
0190  \begin{aligned}
0191  (\mathsf P_2)\quad \min_{\mathbf m_t}\quad&
0192  F_t(\mathbf m_t)=\sum_k\pi_kD_{k,t}(m_{k,t})\\
0193  \mathrm{s.t.}\quad&\sum_kw_{k,t}(m_{k,t})\le B,\\
0194  &m_{k,t}\in\{1,\ldots,d\},\quad\forall k.
0195  \end{aligned}
0196  \label{fkl:prob:counts}
0197 \end{equation}
0198 
0199 \begin{proposition}
0200 For $U_t>0$, $B>0$, and $c_{k,t}>0$, problems $\mathsf P_1$ and $\mathsf P_2$ have identical feasible retained-count vectors and optimal reconstruction objectives. Every feasible $\widehat{\mathbf m}_t$ yields a feasible joint allocation through~\eqref{fkl:eq:bandwidth-recovery}.
0201 \end{proposition}
0202 \begin{proof}
0203 The time equalities uniquely impose $B_{k,t}=w_{k,t}(m_{k,t})$. Their sum satisfies~\eqref{fkl:eq:bandwidth-budget} exactly when the reduced resource constraint holds. Conversely, assigning these bandwidths to any feasible count vector satisfies each time equality. Equation~\eqref{fkl:eq:exact-kl} gives the same objective in both problems.
0204 \end{proof}
0205 The same count-feasibility condition also characterizes a model with $T_{k,t}^{\UL}\le U_t$: any feasible bandwidth can be reduced to its required value when no additional lower bandwidth limits are imposed. Equality is the selected recovery policy, not a reason to restrict counts to special ratios.
0206 
0207 \subsubsection{Feasibility and Endpoint Cases}
0208 Require $U_t>0$ and positive channel efficiencies. Define
0209 \begin{equation}
0210  W_t^{\min}=\sum_k\min\{w_{k,t}(1),w_{k,t}(d)\},\qquad
0211  W_t^{\dense}=\sum_kw_{k,t}(d).
0212  \label{fkl:eq:endpoint-costs}
0213 \end{equation}
0214 The minimum uses only these two endpoints because the sparse payload increases with $m$. If $W_t^{\min}>B$, the prescribed all-client problem is infeasible. If $W_t^{\dense}\le B$, full retention attains the global lower limit $F_t=0$. Otherwise, resource allocation is required, although zero scores may still permit a zero-distortion sparse solution.
0215 
0216 The dense exception is material: a near-dense sparse message with $d+2bm\ge2bd$ is weakly dominated by the dense message, which uses no more bandwidth and has zero reconstruction cost. Consequently, the payload is not globally increasing over $m=1,\ldots,d$. All comparisons below use the exact piecewise expression~\eqref{fkl:eq:uplink-payload}.

0219 \subsection{Lagrangian Decomposition and KL-Threshold Allocation}
0220 \label{fkl:sec:solution}
0221 We use only a shared-price Lagrangian method for the proposed allocator. Bandwidth elimination is exact, whereas the remaining integer allocation is approached through exact local price responses, a coordinated price search, and an explicitly feasible incumbent. General dual-decomposition and KKT concepts follow~\cite{decomposition,boyd}; the formulas below specialize them to the stated FedKLS objective.
0222 
0223 \subsubsection{Separable Local Price Problems}
0224 Suppress $t$ for this section. Introduce a multiplier $\lambda\ge0$ for the bandwidth constraint. The Lagrangian separates as
0225 \begin{equation}
0226  \mathcal L(\mathbf m,\lambda)
0227  =\sum_k\left[\pi_kD_k(m_k)+\lambda w_k(m_k)\right]-\lambda B.
0228  \label{fkl:eq:lagrangian}
0229 \end{equation}
0230 For a broadcast price, each client returns
0231 \begin{equation}
0232  m_k(\lambda)\in
0233  \argmin_{m\in\{1,\ldots,d\}}
0234  \underbrace{\left[\pi_kD_k(m)+\lambda w_k(m)\right]}_{F_k(m;\lambda)}.
0235  \label{fkl:eq:local-price}
0236 \end{equation}
0237 The client needs its own scores, $\pi_k$, $U$, and $c_k$, but not another client's posterior. The server coordinates the common price and checks the shared resource constraint. The price $\lambda$ is distinct from any regularization coefficient used in local Bayesian training.
0238 
0239 \subsubsection{Exact Sparse Threshold and Dense Comparison}
0240 For $1\le m\le d-2$, both $m$ and $m+1$ use the sparse format. The change in the local priced objective is
0241 \begin{align}
0242  F_k(m+1;\lambda)-F_k(m;\lambda)
0243  &=-\pi_ks_{k,(m+1)}+\lambda\frac{2b}{Uc_k}.
0244  \label{fkl:eq:marginal-change}
0245 \end{align}
0246 Thus the next pair is worth retaining when
0247 \begin{equation}
0248  s_{k,(m+1)}>\theta_k(\lambda),\qquad
0249  \theta_k(\lambda)=\frac{2b\lambda}{\pi_kUc_k}.
0250  \label{fkl:eq:threshold}
0251 \end{equation}
0252 Let $N_k(\lambda)=\#\{i:s_{k,i}>\theta_k(\lambda)\}$. Because scores decrease with rank, a sparse minimizer is
0253 \begin{equation}
0254  m_k^{\spc}(\lambda)
0255  =\min\{d-1,\max\{1,N_k(\lambda)\}\}.
0256  \label{fkl:eq:sparse-response}
0257 \end{equation}
0258 Strict thresholding selects the lowest-count sparse minimizer when scores equal the threshold. A deterministic coordinate-index rule resolves score ties when constructing the actual message.
0259 
0260 The full-retention option must be compared separately:
0261 \begin{align}
0262  F_k^{\spc}(\lambda)
0263  &=\pi_kD_k(m_k^{\spc})
0264  +\lambda\frac{d+2b m_k^{\spc}}{Uc_k},\label{fkl:eq:sparse-price}\\
0265  F_k^{\dense}(\lambda)&=\lambda\frac{2bd}{Uc_k}.
0266  \label{fkl:eq:dense-price}
0267 \end{align}
0268 Choose the candidate with smaller priced objective; in a tie choose the smaller required bandwidth, then the smaller discarded KL if necessary. Equations~\eqref{fkl:eq:sparse-response}--\eqref{fkl:eq:dense-price} solve~\eqref{fkl:eq:local-price} exactly in mathematical arithmetic. In particular, the bitmap is included even though its constant cost cancels in~\eqref{fkl:eq:marginal-change}.
0269 
0270 The resulting count is an integer computed from current scores, not an entry in a predefined ratio list. For fixed price, stronger channels and larger aggregation weights lower the threshold. Equivalently, the marginal benefit per additional Hz on the sparse branch is
0271 \begin{equation}
0272  \rho_{k,i}=\frac{\pi_kUc_ks_{k,i}}{2b},
0273  \label{fkl:eq:priority}
0274 \end{equation}
0275 and the threshold retains marginal entries with $\rho_{k,i}>\lambda$.
0276 
0277 \subsubsection{Server Price Search}
0278 Define the total required bandwidth and the response objective by
0279 \begin{equation}
0280  G(\lambda)=\sum_kw_k(m_k(\lambda)),\qquad
0281  F(\mathbf m(\lambda))=\sum_k\pi_kD_k(m_k(\lambda)).
0282  \label{fkl:eq:demand}
0283 \end{equation}
0284 For exact local minimizers, $G(\lambda)$ is nonincreasing, including dense-format switches. Indeed, let $m_1,m_2$ minimize one client's priced objective at $\lambda_1<\lambda_2$. Adding the two optimality inequalities gives
0285 \begin{equation}
0286  (\lambda_2-\lambda_1)\big[w_k(m_2)-w_k(m_1)\big]\le0.
0287  \label{fkl:eq:monotonicity}
0288 \end{equation}
0289 Summing over clients proves the claim. The dense exception prevents replacing bandwidth demand by an unqualified count-only proxy; the server evaluates the actual piecewise payload at every query.
0290 
0291 The server increases the price when $G(\lambda)>B$ and decreases it when a lower price may preserve more information while remaining feasible. It maintains a bracket with an infeasible low-price response and a feasible high-price response, and queries midpoint prices. An initial high price can be doubled until a feasible response is found, subject to a finite iteration and numerical-safety limit. At every query, the best feasible vector is retained rather than blindly accepting the last trial. A minimum-bandwidth vector from~\eqref{fkl:eq:endpoint-costs} provides a feasible fallback whenever the problem is feasible.
0292 
0293 After choosing $\widehat{\mathbf m}$, the server grants
0294 \begin{equation}
0295  \widehat B_k=\frac{L_k(\widehat m_k)}{Uc_k},\qquad
0296  \widehat r_k=\frac{\widehat m_k}{d}.
0297  \label{fkl:eq:final-allocation}
0298 \end{equation}
0299 Thus every idealized upload takes $U$ and the common completion target is met. Reallocating unused bandwidth to accelerate uploads would constitute a different completion policy, not the equality recovery in~\eqref{fkl:eq:final-allocation}.
0300 
0301 \subsubsection{Dual Bound, Stopping Rule, and Optimality Scope}
0302 The dual function is
0303 \begin{equation}
0304  g(\lambda)=\sum_k\min_{1\le m\le d,\,m\in\mathbb Z}
0305  \left[\pi_kD_k(m)+\lambda w_k(m)\right]-\lambda B.
0306  \label{fkl:eq:dual}
0307 \end{equation}
0308 For any feasible incumbent $\widehat{\mathbf m}$ and $\lambda\ge0$,
0309 \begin{equation}
0310  g(\lambda)\le F^\star\le F(\widehat{\mathbf m}),
0311  \label{fkl:eq:gap-bound}
0312 \end{equation}
0313 where $F^\star$ is the optimal value of~\eqref{fkl:prob:counts}. The first inequality follows because the Lagrangian is no greater than the primal objective at any feasible point, and $g$ minimizes that Lagrangian. The second follows from feasibility. No strong-duality assumption is needed.
0314 
0315 Over the queried prices, record
0316 \begin{equation}
0317  \mathrm{LB}=\max\{0,\max_jg(\lambda_j)\},\qquad
0318  \mathrm{UB}=F(\widehat{\mathbf m}).
0319  \label{fkl:eq:bounds}
0320 \end{equation}
0321 A requested reconstruction-objective accuracy is certified when
0322 \begin{equation}
0323  \mathrm{UB}-\mathrm{LB}
0324  \le\varepsilon_{\mathrm{abs}}+
0325  \varepsilon_{\mathrm{rel}}\max\{1,\mathrm{UB}\}.
0326  \label{fkl:eq:gap-stop}
0327 \end{equation}
0328 A price-interval tolerance or iteration cap may also stop the algorithm, but does not by itself certify this objective accuracy. If exact local responses are feasible and satisfy
0329 \begin{equation}
0330  \lambda\left(G(\lambda)-B\right)=0,
0331  \label{fkl:eq:complementarity}
0332 \end{equation}
0333 then $g(\lambda)=F(\mathbf m(\lambda))$, which certifies a global integer optimum for that instance.
0334 
0335 In general, integer counts cause stepwise demands and can leave a nonzero duality gap. Bisection cannot recover every feasible integer combination. For illustration, after mandatory minimum allocations, suppose one optional pair costs two bandwidth units and reduces weighted KL by three, while another costs three units and reduces KL by four. A remaining budget of three units favors the second pair alone, but a common price selects the first pair whenever it selects the second. This illustrates why exact local thresholding does not automatically yield a globally optimal integer allocation. The separate dense format adds another nonconvex feature.
0336 
0337 For a KKT interpretation, linearly interpolate $D_k$ between consecutive integer counts and restrict to the sparse branch. On $x\in[j,j+1]$,
0338 \begin{equation}
0339  \overline D_k(x)=D_k(j)-(x-j)s_{k,(j+1)}.
0340  \label{fkl:eq:interpolation}
0341 \end{equation}
0342 Its slopes are nondecreasing, hence it is convex. Interior KKT stationarity for this continuous relaxation~\cite[Sec.~5.5]{boyd} gives
0343 \begin{equation}
0344  0\in\pi_k\partial\overline D_k(x_k)+\lambda\frac{2b}{Uc_k}.
0345  \label{fkl:eq:kkt}
0346 \end{equation}
0347 At an interior integer breakpoint, this is
0348 \begin{equation}
0349  \pi_ks_{k,(m_k)}\ge\frac{2b\lambda}{Uc_k}
0350  \ge\pi_ks_{k,(m_k+1)}.
0351  \label{fkl:eq:kkt-threshold}
0352 \end{equation}
0353 These conditions explain the threshold but do not make the original discrete problem convex. Accordingly, a returned feasible solution is denoted $\widehat{\mathbf m}$, not $\mathbf m^\star$ unless certified.

0399 \subsubsection{Feasible Refinement and Computational Cost}
0400 Procedure~1 may be followed by a bounded refinement that adds affordable posterior pairs according to~\eqref{fkl:eq:priority}, and checks switches to the dense format using their actual bandwidth difference. Accept only feasible changes that do not increase the reconstruction objective. Such additions can improve the incumbent, but are not a global-optimality proof and do not remove a duality gap in general. Previously valid dual bounds remain lower bounds after refinement.
0401 
0402 A complete score sort and a reverse cumulative sum cost $O(d\log d)$ time and $O(d)$ storage at each client using a comparison sort. Afterwards, a binary search in sorted scores determines the threshold count in $O(\log d)$ time; tail evaluation and dense comparison are constant-time. Each price query uses $O(K)$ server arithmetic and a small response from each client, rather than uploading every coordinate score. With $J$ price queries, reporting scales as $O(KJ)$ scalar messages. This is a computational and signaling tradeoff, not a guarantee that repeated control exchanges have negligible elapsed time.

0407 \subsubsection{Separation of Learning and Allocation}
0408 Keep the existing local FOLA training and FedKLS reconstruction/aggregation intact. Introduce the wireless simulator and allocator as separate modules so that changing the resource policy does not silently change the local learner. A suggested interface is given in Table~\ref{fkl:tab:modules}. These are implementation contracts, not claims of completed training experiments.

0428 For a simulated round, obtain the global posterior and downlink duration, execute each client's full local preparation, and compute $U_t$ using the maximum preparation duration. Refresh or generate channel conditions for the allocation/upload phase; do not assume an old channel measurement remains valid through arbitrarily long local training. The server then invokes Procedure~1. In an initial single-process simulator, client-response calls may be local function calls, but the server must not use the clients' full score vectors for decisions beyond the specified response interface. Account separately for the network exchanges those calls represent.

0430 After a grant, client $k$ selects its stored top-$\widehat m_{k,t}$ indices and serializes the corresponding pairs. It does not train again during the price search. The server fills omitted marginals with the broadcast global values and preserves the original normalized weighted product~\cite[Sec.~II-A]{fedkls}:
0431 \begin{equation}
0432  q_{t+1,0}(\boldsymbol\theta)
0433  \propto\prod_{k\in\mathcal K}
0434  \widetilde q_{k,t}(\boldsymbol\theta)^{\pi_k}.
0435  \label{fkl:eq:aggregation}
0436 \end{equation}
0437 Do not renormalize $\pi_k$ separately over only those clients that transmitted a particular coordinate; that would change the agreed prior-fill aggregation rule.

0439 \subsubsection{Numerical and Feasibility Safeguards}
0440 Use one source of truth for the piecewise payload in~\eqref{fkl:eq:uplink-payload}. Validate $U_t>0$, finite positive $c_{k,t}$, $1\le\widehat m_{k,t}\le d$, and
0441 \begin{equation}
0442  \sum_k\widehat B_{k,t}\le B,\qquad
0443  \frac{L_k(\widehat m_{k,t})}{\widehat B_{k,t}c_{k,t}}=U_t
0444  \label{fkl:eq:postconditions}
0445 \end{equation}
0446 up to declared numerical tolerances. Never round an infeasible count upward to one or silently exclude a client. A violated all-client requirement must return an infeasibility status for the experiment controller to handle explicitly.
0447 
0448 Compute score sums and objective comparisons in at least float64 for the initial numerical implementation. Construct tail sums by reverse accumulation rather than subtracting a nearly equal prefix from the total. Validate positive finite variances; apply the same damping/flooring convention to all compared learners. For variance ratio $v_0/v_k=1+u$, the variance contribution $u-\log(1+u)$ can be evaluated with a numerically stable logarithm near $u=0$. Reject nonfinite scores and distinguish tiny roundoff negatives from genuinely invalid inputs.
0449 
0450 Use deterministic score ties and dense/sparse cost ties. A numerically approximate local response need not achieve the exact local Lagrangian minimum; its evaluated value is then not automatically a valid dual lower bound. Mathematical certificates in~\eqref{fkl:eq:gap-bound} require exact local minimization or rigorously bounded numerical errors. Without such error control, label the reported gap as a numerical diagnostic. Price iterations should have explicit limits and return the best feasible incumbent on termination.
0451 
0452 The initial channel model fixes PSD, not total transmit power. Log $P_{k,t}=p_{k,t}^{\mathrm{PSD}}\widehat B_{k,t}$ and, under the equality timing policy, $E_{k,t}^{\UL}=P_{k,t}U_t$. If an experiment instead fixes total power, replace the rate and rederive the allocation cost; do not merely recompute SNR once and reuse the fixed-$c$ threshold.

0454 \subsubsection{Equal-Bandwidth Baseline and Controlled Comparisons}
0455 Use Version A as a baseline under the same reporting barrier and round target. Assign $B_{k,t}^{A}=B/K$ and define $Q_{k,t}=U_t(B/K)c_{k,t}$. Check $Q_{k,t}\ge2bd$ first, in which case $m_{k,t}^{A}=d$. Otherwise use
0456 \begin{equation}
0457  m_{k,t}^{A}
0458  =\min\left\{d-1,
0459  \left\lfloor\frac{Q_{k,t}-d}{2b}\right\rfloor\right\},
0460  \label{fkl:eq:version-a}
0461 \end{equation}
0462 only when the result is at least one. Infeasibility under equal bandwidth does not imply infeasibility under joint allocation. The baseline transmits within $U_t$ and can finish early; the equality-based policy recovers its own bandwidths using~\eqref{fkl:eq:final-allocation}.
0463 
0464 If Version A is feasible, its counts are feasible for the reduced joint problem because
0465 \begin{equation}
0466  \sum_kw_{k,t}(m_{k,t}^{A})\le\sum_k B/K=B.
0467  \label{fkl:eq:baseline-incumbent}
0468 \end{equation}
0469 Initializing the feasible incumbent with this vector guarantees that the returned frozen-round reconstruction objective is no worse than Version A's, since it is never replaced by a worse feasible candidate. This statement compares identical local posteriors in one round; it does not guarantee higher accuracy or domination along separate training trajectories.
0470 
0471 Start validation with frozen local posteriors. On small synthetic cases, compare the local threshold response against evaluation of all integer counts and compare the complete feasible solution against exhaustive enumeration of the tiny joint count space. Include zero scores, repeated scores, the dense exception, an all-dense feasible budget, an infeasible minimum budget, and heterogeneous $c_k$. Test that bandwidth demand is nonincreasing over increasing prices, that~\eqref{fkl:eq:postconditions} holds, and that valid lower and upper bounds bracket the tiny-instance optimum.
0472 
0473 Then evaluate repeated federated training using matched initial models, local data partitions, channel draws, training settings, and round targets. Compare joint KL-aware allocation with feasible equal-bandwidth adaptation and a uniform-retention baseline. A random-selection ablation should match retained counts and assigned bandwidths to isolate the coordinate selector. Record accuracy and calibration versus cumulative time, reconstruction objective, count distributions, bandwidths, power/energy, price-query counts, feasibility failures, and objective gaps.
0474 
0475 \subsubsection{Overhead Accounting and Scope of Claims}
0476 The analytical round target omits price messages and server computation, but code should separately record or model both. Wall-clock time for in-memory function calls is not wireless-report latency. If their contribution is material, reserve a control-time allowance before allocation or explicitly subtract it from the upload budget. A finite price-query cap makes such an allowance operationally meaningful. Keep simulated parallel client durations separate from the sequential runtime of a single-machine simulation.
0477 
0478 Under a fixed round duration, the intended benefit is better posterior preservation and potentially better learning within the same time budget, not an automatic reduction in per-round latency. The exact results are the reconstruction identity, bandwidth elimination, local priced solution, and conditional dual-bound certificate. The proposed price-based integer allocation is feasible by construction when the safeguards succeed, but is not universally globally optimal. Improved convergence, accuracy, calibration, and negligible control overhead remain hypotheses to be evaluated through the implementation.
